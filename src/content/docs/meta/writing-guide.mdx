攻略页的核心是「读者正在解决什么问题」。先给结论、适用范围和风险，再补背景。

## 页面开头

每页尽量写清：

| 字段 | 说明 |
| --- | --- |
| 游戏名 | 方便搜索结果和跨游戏引用 |
| 适用版本 | 版本号、赛季、补丁或最后验证日期 |
| 内容状态 | 草稿、待验证、已验证、已过期 |
| 适用范围 | 新手、后期、某角色、某地图、某玩法 |

建议在正文开头使用：

```mdx
<div className="leaf-meta-row">
  <span className="leaf-badge">版本：1.0</span>
  <span className="leaf-badge" data-status="verified">已验证</span>
  <span className="leaf-badge">最后验证：2026-06-23</span>
</div>
```

## 标题

标题直给，优先使用玩家会搜索的词：

| 推荐 | 不推荐 |
| --- | --- |
| 新手开荒路线 | 初入异世的冒险 |
| 角色配装 | 强者之路 |
| 地图收集点 | 遗落角落 |
| 材料速刷路线 | 每日功课 |

## 表格

数值、材料、掉落、路线对比优先用表格。表格列名要短，单元格尽量只放一个信息点。

## 待验证内容

不确定的信息可以写，但要标明：

:::caution[待验证]
这里写当前观察、猜测来源、缺少什么样的验证。
:::

## 更新记录

每个游戏目录保留 `changelog.mdx`。当页面结论变动、版本迁移、路线失效时，在更新记录里留一行。
